# Lumeri module interfaces

Acrab, 2026-10-22: every part of Lumeri is a Luc, and every part has a defined
interface. The interface is the backbone. A part may be replaced; its
interface must be kept. This holds for all parts.

This page is the one place that says what an interface is and how it is kept.
The contracts are the files under `contracts/interfaces/`. The checker
`scripts/luc_interfaces.py check` and `tests/test_luc_interfaces.py` hold this
page, those files and the code together.

It builds on the self-Luc rules (Acrab, 2026-10-17; `docs/self-luc-spec.html`):
an original is never changed, a replacement is only a layer on top, taking the
layer off restores the original, and a broken layer falls back to the original
by itself. This page adds what those rules left open: *what* a replacement must
keep, written down per module, so it can be checked.

## Words

One word, one meaning (Acrab, 2026-10-11).

| Word | Meaning |
|---|---|
| Module | One part of Lumeri: one row of `docs/luc/self-luc-inventory.md`, or a piece of such a row. Every module is a Luc, or will be. |
| Interface | What a module promises whoever calls it: its operations, their inputs and outputs, the events it emits, the errors it may return, its bounds, its reach, and its rules. Id `iface:<dotted.name>/v<major>`. |
| Contract | The file that writes one interface down: `contracts/interfaces/<area>/<name>.v<major>.json`. |
| Protocol | Unchanged: how a Luc package talks to the Host (`lumeri.tool/v2`, `lumeri.panel/v2`, ...). An interface is reached over one carrier, which may be a protocol. |
| Original | What Lumeri ships today for a module. It is the reference implementation: every rule of a contract is first checked against the original. |
| Replacement | A layer (Extension) on the module's Luc that takes over what the module does. It keeps the interface. |

## The rules

1. **Every module has an interface.** No module exists without a contract.
   Each area's `index.json` lists its modules; together they cover every row
   of the inventory, and every capability of every Official Luc is an
   operation of exactly one interface.
2. **The contract is the authority, not the code.** When the original and its
   contract disagree, one of them is wrong. The difference is written in the
   contract's `known_deviations`, with a strict-xfail test where one can be
   written. It is never left silent.
3. **A replacement keeps the whole interface.** Same interface id and major;
   every operation, by the same name and capability id; it accepts every
   input the contract's input schema accepts; every output it gives is valid
   against the output schema; it returns only the error codes the contract
   lists (the Runtime's own codes aside); it emits only the events the
   contract lists, with valid payloads; it stays inside the reach (permissions,
   Host APIs, editable boundary; what the creator approves for their own
   machine aside, see `reach` below) and the bounds (deadlines, sizes); and
   the contract's invariants hold for it.
4. **Checked at load and at run.** At load, before a layered Luc reaches the
   Host, `lumeri_runtime/luc_interface_gate.py` compares it with its module's
   contracts and leaves its layers off by name (`E_LUC_INTERFACE_*`); the Luc
   loads as it shipped. The contracts it reads ship inside the Runtime as
   `lumeri_runtime/luc_interface_table.py`, generated by `render`, so the
   Runtime never reads `contracts/` from disk. At run an output outside the
   schema, an error code not listed, an event not listed or a deadline missed
   is a break: the run gate of the self-Luc rules sends the call back to the
   original and says so.
5. **Versions.** A contract's `version` is `major.minor.patch`. A minor version
   may only add: an optional input field, a new operation, a new event, a
   wider bound. Anything else (a removed or renamed operation, a narrower
   input, a wider output, a new required field, a narrower bound) is a new
   major, which is a new interface id. Two majors may be offered side by side;
   a replacement names the one it keeps.
6. **Who may replace a module** is the contract's `replaceability.class`:
   - `open`: any creator's layer, from a folder or an approved profile.
   - `reviewed`: a layer granted only by Lumeri's review receipt naming its
     exact bytes (as `agent.replace` is today). Until Lumeri can review a
     layer, no layer lies on such a Luc.
   - `sandboxed`: a replacement carries code, and that code runs only in the
     code sandbox (self-Luc decision 2; Acrab approved the sandbox on
     2026-10-26). A layer may change the Luc's manifest (its words, a
     narrower reach) and never its own files; on an Official tool it may add
     a program that answers for a capability ([tool-programs.md](tool-programs.md)).
     The agent loop has one too (Phase 2 below): its program runs fenced, and
     only from a Luc that also holds the reviewed `agent.loop`.
   - `lumeri-only`: the foundation. Only Lumeri replaces it, through a signed
     Official channel or a new Runtime: accounts, gateway and cloud (Acrab,
     2026-10-06); the model route, budgets and receipts; the layering
     machinery itself; the editor page's shell and its native bridge.
     A creator's layer on such a Luc changes only what the contract's
     `replaceability.layer_may_patch` names (the workspace's module list,
     Acrab 2026-10-24), and nothing where it names nothing.
   A `lumeri-only` interface is still written and still held by tests, so
   Lumeri's own changes keep it too, or bump its major. Changing a module's
   class is Acrab's decision and is recorded in `replaceability.decided`.

   A replacement may also be another Luc altogether. A workspace module the
   Official workspace fills with a Panel is a role, held to that Panel's
   interface (its contract's `carrier.workspace_module`; Acrab, 2026-10-24).
   Another Luc's Panel placed there, through a layer on the workspace's module
   list, fills it only while it keeps that interface within its reach;
   otherwise the role's own Panel takes the module back
   (`iface:editor.placement/v1`).
7. **The iron rule stands.** Writing an interface changes no original.
   Enforcing one is new code at the seams, never an edit of what a module does.
8. **English.** Contracts are read by agents: every text in them is English,
   every letter ASCII (the 2026-10-06 rule for the Luc-agent protocol).
9. **One truth.** A schema that is already a contract (the Runtime contract in
   `contracts/runtime-v1/runtime-contract.json`, the schemas in
   `docs/luc/schemas/`) is pointed at, not copied. A schema that today lives
   only in code (a packaged tool's `parameters`) is written into the contract,
   and the checker proves the code still equals it. A contract never points
   into code for a schema; code is only cited as evidence.

## A contract file

Format `lumeri.interface/v1`, JSON, checked by
`contracts/interfaces/interface-contract-v1.schema.json`. Fields:

- `id`: `iface:<dotted.name>/v<major>`. The file is
  `contracts/interfaces/<area>/<dotted.name>.v<major>.json`.
- `version`: `major.minor.patch`; its major equals the id's.
- `area`: `tools`, `editor`, `agent`, `data`, `process` or `machinery`.
- `title`, `summary`: what the module is for, in a line and a paragraph.
- `carrier`: how callers reach it. `kind` is one of
  - `luc-protocol` (with `protocol`, e.g. `lumeri.tool/v2`),
  - `http` (Gateway or Worker routes),
  - `event` (Session event kinds),
  - `python` (an in-process call in the Runtime; `seam` names `module:function`),
  - `subprocess` (a child process speaking JSON, e.g. `lumeri-engine`),
  - `browser` (the editor page's JavaScript or a frame's messages),
  - `file` (data at rest: a file format or a config table),
  - `native` (the App shell and the Runtime, or the page and the App).
- `replaceability`: `class` (rule 6), `why`, `decided` (who decided, when),
  and for a `lumeri-only` interface the optional `layer_may_patch`: JSON
  pointers into the module's Luc manifest that a layer may still change.
- `reach`: the ceiling a replacement must stay under: `permissions`,
  `host_apis`, `editable` (`none` or target types, properties, areas, as in a
  Luc manifest), and optional `bridge_calls` for a Panel. The authority rules
  hold a layer to it: a layer from the lucs folder reaches nothing its Luc did
  not, and the creator may approve more in the Luc's activation profile for
  their own machine, never what only Lumeri gives (`docs/luc/permissions.md`).
  A Panel's bridge events, which no authority names, are held by the load
  gate to the contract's `events`.
- `operations`: one per call a caller can make. Each has `name`; optional
  `capability` (the Luc capability id, when it is one); `effect` (`none`,
  `read`, `write`, `paid`, `process`); `input` and `output` (a JSON Schema
  draft 2020-12, or `{"$contract": "<file>#<json-pointer>"}` into another
  contract file); `errors` (the codes it may return); `deadline_ms` (or
  `null` with the reason in `notes`); `idempotency` (`none`, `natural`,
  `client_op_id`, `idempotency_key`, `execution_id`); `status` (`defined`
  when it was read off the original, `draft` when part of it is a guess, with
  the guess said in `notes`); `evidence` (code citations).
- `events`: what the module emits, each with `name`, `payload` schema and
  `evidence`.
- `bounds`: named limits with `value`, `unit` and `evidence`.
- `invariants`: rules every implementation keeps, each with `id`, `text` and
  `test` (a pytest node id that holds it today, or `null` when none does yet).
- `failure`: `break` (what counts as a break) and `fallback` (`original`,
  `official-panel`, `builtin-view`, `refuse`, `fail-closed`), with `evidence`.
- `conformance`: `status` (`exists`, `partial`, `planned`) and `tests`.
- `known_deviations`: where the original disagrees with this contract today.
- `open_questions`: what is not decided, and for whom (`acrab` or `lumeri`).
- `definitions` (optional): named schemas this contract owns. Its own
  operations and other contracts point at them with
  `{"$contract": "contracts/interfaces/<area>/<file>#/definitions/<name>"}`;
  a shape that belongs to one module (the timeline document, an error
  envelope) is defined once, in that module's contract.

Evidence is `path:line` or `path:start-end`, relative to the repository root.
A path in another repository starts with `~/` and is not checked here.

## The index

Each area has `contracts/interfaces/<area>/index.json` (format
`lumeri.interface-index/v1`): one entry per module with `module` (its Luc id,
or the Luc id it will have: `lumeri.<name>`), `inventory` (the inventory row it
comes from, exactly as written there), `status` (`luc`, `partly`, `not-yet`)
and `interfaces` (the ids it provides). A module id appears once across all
areas. An inventory row may be split over several modules.

## What the checker holds

`scripts/luc_interfaces.py check` (run by `tests/test_luc_interfaces.py`):

- every contract is valid against the format schema, its id matches its file
  and its area, and its major matches its version;
- every evidence path exists and every cited line is inside the file;
- every `$contract` pointer resolves;
- every invariant test names a test file that exists and a test in it;
- every module id is unique, every interface an index names exists, every
  contract is named by some module, and every inventory row is covered;
- every capability of every Official Luc manifest is the `capability` of
  exactly one operation, in an interface its own module provides;
- for every packaged tool (`lumeri.tool/v2`), the operation's `input` equals
  the tool's `parameters` in the shipped code, byte for byte as JSON;
- for every interaction (`lumeri.interaction/v1`), the operation's `input` and
  `output` equal the capability's shipped `input_schema` and `output_schema`,
  with their `$defs` references written out;
- every surface an Official capability declares is its interface's carrier
  surface, and every Official Luc reaches no further than its interfaces'
  reach (permissions, Host APIs, editable boundary, bridge calls);
- `layer_may_patch` appears only in a `lumeri-only` contract, and each pointer
  names a part of the module's manifest;
- a `workspace_module` is on a `lumeri.panel/v2` interface of one Panel of one
  module, no two interfaces name the same module, and the roles are exactly
  the Panel modules of the Official workspace, each holding the Panel the
  workspace places there.

`scripts/luc_interfaces.py list` prints the modules with their interfaces and
classes; `render` writes `docs/luc/interfaces-catalog.md` and
`lumeri_runtime/luc_interface_table.py` (the interface rows and the roles) from
the contracts, and
`render --check` says whether either is out of date.

## Where this stands

Phase 1 (2026-10-22, branch `luc/interfaces`): this page, the format, the
checker and a contract for every module; the checker holds the originals to
their contracts.

Phase 2, each step its own change:

- Load gate (2026-10-24, done): the table, `luc_interface_gate` and its two
  hooks (`luc_local.lay_on`, and `official_luc.bootstrap_official_lucs` right
  after `_creator_layers`), held by
  `tests/test_luc_interface_gate.py`. A layer keeps every capability, its
  protocol, surface, names and schemas, a Panel's bridge events, and what its
  module's class allows; otherwise it is left off and the Luc loads as it
  shipped. A capability a layer adds is its own, outside the interface.
- Roles (2026-10-25, done): `luc_interface_gate.role_reason` and
  `luc_workspace.workspace_catalog`, held by `tests/test_luc_workspace_roles.py`.
  Another Luc's Panel fills a role while it is loaded, keeps the role's
  protocol and surface, and calls, edits and hears no more than the role's
  interface; one that does not gives the module back to the role's own Panel
  and registers itself. One that breaks in use gives it back for the rest of
  the start (`luc_interactions.fall_back`), not counted by `luc_breaker`.
- Agent loop (2026-10-25, in part): the agent core is a module Luc,
  `lumeri.agent.loop`, held to `iface:agent.loop/v1`. `agent_turn.AgentTurn`
  asks `luc_agent_loop.drive` for each next step when a Luc holding the
  reviewed `agent.loop` brings a program (protocol `lumeri.agent.loop/v1`);
  the program runs under `luc_sandbox` with no files, no network and an empty
  environment, one JSON line each way, and only decides: the Runtime still
  asks the model, runs the tools, keeps the conversation and stops a repeated
  call. Any break (a late, oversized or out-of-shape answer, an action it may
  not take, an exit) hands the turn to the original from the last action
  performed, with nothing asked or run twice, and the original decides for
  the rest of the start (`luc.module_fell_back`, `luc_breaker`). Held by
  `tests/test_luc_agent_loop.py`; written up for Luc authors in
  [agent-loop.md](agent-loop.md). Acrab approved its sandbox and numbers on
  2026-10-26; a checkpoint is not yet read back after a Worker crash.
- Tool programs (2026-10-26): every Official agent tool (a `lumeri.tool/v2`
  Luc whose interface is sandboxed: 15 Lucs, 17 interfaces, 27 capabilities)
  can be replaced. A layer, from the lucs folder or a profile, adds a program
  and names it in a capability's `program`; the agent's call then goes to the program in the
  sandbox, which reaches the Project only through ToolHost's calls over the
  pipe (`luc_tool_program`, protocol `lumeri.tool.program/v1`). Its answer
  must keep the contract's output schema or name one of its error codes;
  anything else hands the call to the Official code, which answers for that
  Luc for the rest of the start (`luc.module_fell_back`, `luc_breaker`). A
  call whose program had already changed the Project is refused instead
  (`E_LUC_PROGRAM_BROKE`). Held by `tests/test_luc_tool_program.py`, which
  also runs a compiled sample (`examples/luc-tool-program`); written up in
  [tool-programs.md](tool-programs.md).
- Agent parts (2026-10-26): the four parts the agent turn leans on
  (`lumeri.agent.request-window`, `.guidance`, `.conversation`,
  `.native-toolbox`) can each be answered by a program a Luc holding the
  reviewed `agent.loop` brings (protocol `lumeri.agent.part/v1`), in the
  agent loop's sandbox, one process per answer. The Runtime holds every answer
  to what the original could have answered; any break has the original answer
  the same call and every call of that part for the rest of the start
  (`luc.module_fell_back`, `luc_breaker`). Held by
  `tests/test_luc_agent_parts.py`; written up in
  [agent-parts.md](agent-parts.md).
- Engine programs (2026-10-26): seven data and engine modules
  (`lumeri.media.facts`, `.media.thumbnails`, `.encode.backend`,
  `.lumen.canvas`, `.render.backend`, `.timeline.render`, `.engine.gemia`)
  can each be answered by a program that stands in for FFprobe, FFmpeg or
  `lumeri-engine`, from a Luc holding the reviewed `engine.program`
  (protocol `lumeri.engine.program/v1`). It is started as the original is, in
  the original's sandbox profile but writing only the session scratch; what
  it leaves passes the original's checks and the module's own. Any break has
  the original run the same request, and answer for the module for the rest
  of the start (`luc.module_fell_back`, `luc_breaker`). Held by
  `tests/test_luc_engine_programs.py`, with compiled programs in the media
  sandbox and a real Worker; written up in
  [engine-programs.md](engine-programs.md).
- Transcription (2026-10-27): `lumeri.transcriber.backend` is the eighth
  engine module. Its program stands in for whisper-cli, which the engine runs
  inside its roughcut: `LUMERI_WHISPER_CLI` names the program instead, and
  whisper's JSON it writes must be whisper's, inside the sound it heard. A run
  with it that fails is cleared and run again by the original, and was a break
  only if that run answers. Held by `tests/test_luc_engine_programs.py`, with
  compiled programs run by the real engine in the transcription sandbox.
- Library search (2026-10-27): `lumeri.library.search` may be answered by a
  search program (`lumeri.search.program/v1`, reviewed permission
  `search.program`) in the agent loop's sandbox, one process per search. The
  question is checked by the original's rules first; the program reads each
  asset's id, filename and notes and answers with hits in its own order, each
  one of the library's assets, matched on its own fields and naming only its
  own notes. Anything else is a break and the original answers for the rest of
  the start. Held by `tests/test_luc_search_program.py`, with compiled
  programs and a real Worker; written up in
  [search-programs.md](search-programs.md).
- Point library layers (2026-10-27, Acrab's 3A of 2026-10-24): a `.lup`
  bound to code built into Lumeri converts into a layer on
  `lumeri.vector-motion-library`. The layer brings only the catalog and
  verification it names; the Luc keeps the code and its pins. With the layer
  on, the agent's catalog read answers with the layer's data. Switched off or
  taken away, Lumeri's own library answers. A layer that changes a pin, brings
  another file or is not English is left off alone. Held by
  `tests/test_luc_library_layer.py`, with a real Worker; written up in
  [library-layers.md](library-layers.md).
- Run gate: the agent loop, its parts, the tool programs, the engine
  programs and the search program above are held at run for code a Luc brings. Elsewhere no layer changes code the Runtime runs: a sandboxed Luc keeps its own files, an interaction's schemas are
  the Host's own, `LucHost.invoke` already validates every input and output
  against the capability's schemas (which the load gate holds to the
  contract), and a Panel that breaks in its frame already falls back
  (`luc_interactions.fall_back`, `luc_breaker`). Once a layer can bring code,
  an error code or event outside the contract, or a missed deadline, counts
  as a break the same way and the call goes back to the original.
- `luc_cli.py conform <extension.luc> [--on <luc>]` (2026-10-24, load gate
  only): says before installing whether an Extension keeps the interface of
  the Luc it lies on, and what authority it would ask for. A contract's
  conformance tests run by it when the run gate exists.
- Modules that are not a Luc yet become Official module Lucs whose capability
  names the built-in original, starting with those whose class is `open` or
  `reviewed`.
