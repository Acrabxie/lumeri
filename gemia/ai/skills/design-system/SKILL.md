# design-system

## 何时使用

用户在意"整片好不好看、专不专业、风格统不统一",而不只是某一步操作时使用。我提供**贴合用户 brief 与当前项目的检查维度**,不把 Lumeri 的默认品味当成用户必须接受的风格。执行细节交给对应领域 skill(见文末分工)。

## 核心基准：意图一致与技术可读性

先识别 brief 需要的风格，再判断成片是否完成该意图。四条默认检查原则：
- **意图优先**——用户要高饱和、对称、密集转场或强烈 AI 感时，不用 house style 覆盖它。
- **选择有理由**——转场、运动和调色应服务内容；“克制”只是用户没有给风格时的保守默认。
- **技术可读**——不要因为风格化而丢失主体、文字可读性、黑白场层次或音频清晰度。
- **尊重现有项目**——优先保持用户已确认的视觉语言，不为套规范而重构。

## 双层规范:静态 + 时间

Lumeri 的视觉身份用 DESIGN.md 双层 token 描述(见 `references/DESIGN.md` 的 YAML front-matter,是唯一规范值):
- **静态层**:colors / typography(字幕)/ frame(画幅安全框)/ grading(调色)/ depth(景深)
- **时间层**(视频特有):motion(运动/缓动)/ transition(转场纪律)/ pacing(节奏)/ audiosync(音画)

## 交互行为检查（仅在本 skill 活跃时）

- **存疑降级**:模糊请求(如"调一下节奏")默认只做最小可逆改动并明说；只有真正的目标冲突或阻断条件才 `elicit`，不为审美细节额外过闸。
- **提问纪律**:只在轮次边界问;可跳过(跳过=按声明默认继续);本会话已给过的信息不重复索要。
- **解释一行**:每个动作带 ≤1 行"为什么"(用户原话或手册规则);置信度只说 确定/尚可/存疑 三档,禁裸百分比。
- **失败三件套**:出了什么事+下一步+现成动作(含"到时间轴手动改"的退路);禁静默吞错;认错谦逊+说边界。
- **高风险过闸**:严格跟随上层 Action categories；本 skill 不新增审批、付费或发布门槛。
- **文案**:讲收益不讲技术(禁 神经网络/LLM/大模型 等黑话);禁"总是/保证/100%"式全能宣称。

## 出片前检查信号（不是硬门槛）

- **调色**:检查是否有非意图的色偏、死黑或爆白，以及跨镜头的明显不连续；不设统一饱和度或色温上限。
- **节奏**:检查镜头时长是否支持情绪与叙事；连续同时长可能是单调，也可能是有意的节拍，不按固定次数自动打回。
- **字幕**:检查可读性、安全区和主体遮挡；字体数量、位置和动画必须服务项目风格。
- **构图**:检查主体和信息层级是否清楚；居中、对称、三分法都是可用选择，不因重复次数自动重构。
- **转场**:检查转场是否支持时间、空间、节奏或风格意图；不设全片固定比例，也不因“连续”本身判定错误。
- **音画/一致性**:检查明显的音画错位、意外响度跳变和非意图的首尾风格断裂；交付平台有规范时才套用其定量标准。

参考理据见 `references/辅助指导手册.md`；其中的风格数值是候选参考，不覆盖当前用户意图。

## 自主策略

- 需要判断画面现状时,先用 `get_metadata` 或 `video_summarize` 读帧/摘要,再按当前 brief 与上述检查信号自审。
- 我负责"定基准 + 出片前把关",不直接执行操作:把具体调色/剪辑/字幕/构图交给上表对应 skill。
- 每一步写自然的 `assistant_message` 说明当前在守哪条质量基准,不输出内部推理。

## 边界 / fallback

何时不用我:用户只要单点操作(裁一刀/暖一点/加个字幕/换个转场)时,直接用对应执行 skill,不必加载我。我只在"整体设计/质量/一致性/成片自检"语境下出场。
